# SwitchWave 项目分析与中文支持

## 分析基线与范围

分析基于上游 master 提交 `e9a7737167e6d316d804e2f0393ba6232c206980`，应用版本 1.1.2。审阅范围包括应用启动与生命周期、渲染线程、mpv 封装、三个 UI 模块、文件系统适配、配置/历史和构建链，以及固定版本 ImGui、mpv 中与字体和字幕编码有关的实现。没有把所有第三方库逐行安全审计，也没有 Switch 实机可供验证。

第一阶段修复中文文件名、元数据、共享名称、字幕与输入。版本 `1.1.2-zh.1` 进一步加入可保存的 English/简体中文界面切换，以及 Explorer 的单文件删除。未改音视频解码后端、主题或音轨/字幕轨道选择偏好。

## 界面语言与单文件删除

- `src/i18n.hpp` 提供英文/简体中文词条和稳定的 ImGui 控件 ID，播放器选项仅翻译显示名称，不改 mpv 的参数名和命令值。
- `Settings` → `Language` 中切换语言，保存到 `SwitchWave.conf` 的 `language=en` / `language=zh-CN`。未知语言值回退为英文。
- Explorer 仅在主文件管理界面提供删除；选中文件后按 X 或点击按钮，确认完整路径后调用对应设备的 `unlink`。默认确认焦点为取消。
- SMB、NFS、SFTP 增加带会话互斥锁的 `unlink_r` 回调，检查连接及普通文件类型，向界面返回库的错误码。HTTP/最近播放/内部存储不开放删除。
- 路径拒绝根目录、跨挂载点、空组件、`.` / `..`、NUL 和反斜杠；删除使用独立保存的原始路径，不从 ImGui 的 `##` 显示标记中解析，避免文件名含标记时误操作。
- 删除不递归、不提供回收站、不绕过服务器权限。目录刷新会重置旧焦点，元数据线程和条目/结果生命周期使用互斥锁保护。
- 目前无实机或真实远程共享删除验收，不能以编译通过代替 SMB 服务器权限与固件环境的测试；请先用可丢弃文件验证。
- 最近播放页面新增「清空最近播放」确认入口；成功关闭历史文件后才清空内存列表并刷新页面，失败显示错误。设置页的历史清理也即时持久化。此按钮不删除媒体、mpv 播放进度、截图、服务器日志或备份，不属于安全擦除。

## 项目结构与数据流

| 模块 | 职责 | 与中文支持的关系 |
| --- | --- | --- |
| `src/main.cpp` | 初始化 Switch 服务、UI、SD/USB/网络资源，切换菜单/播放循环 | 启动时给 mpv 准备字体 |
| `src/render.*` | deko3d 交换链、mpv 渲染上下文、独立渲染线程 | 显示 UI 字体图集和 libass 字幕，二者独立 |
| `src/libmpv.*` | 创建播放器、传递选项、事件/属性/命令封装 | 需要支持字幕编码转换 |
| `src/imgui_impl_hos/imgui_nx.*` | Switch 输入、系统键盘、主题和共享字体 | 决定 UI 能否显示具体汉字 |
| `src/imgui_impl_hos/imgui_deko3d.*` | 字体图集转为 R8 纹理，提交 ImGui 绘制命令 | 不负责文件名转码 |
| `src/ui/ui_explorer.*` | 列举、排序和打开文件，显示路径 | 路径裁切不能截断 UTF-8 |
| `src/ui/ui_main_menu.*` | 媒体预览、配置编辑、网络设置 | 多字节输入/删除和字节容量限制 |
| `src/ui/ui_player.*` | 播放控制、轨道信息、参数和控制台 | 元数据、字幕轨道名称和中文控制台输入 |
| `src/fs/*` | SD/devoptab、USB、SMB、NFS、SFTP、HTTP、最近播放 | 保留协议返回的路径；HTTP 按 UTF-8 字节进行 URL 转义 |
| `src/context.*`、`src/utils.hpp` | 配置、共享定义、固定容量字符串与工具 | 字符数不能替代字节容量 |
| `Makefile`、`Dockerfile`、`.github/workflows/build.yml` | 固定子模块、交叉编译、打包 | 必须真正编入 iconv，不能只改 mpv.conf |

文件名经过文件系统适配进入 `std::string`，最后由 ImGui 按 UTF-8 解码显示。字幕走 mpv → 编码转换 → libass → deko3d，与 UI 字体不是同一个渲染通道。因此只扩充 UI 字库不能解决旧编码字幕，只加字幕字体也不能解决目录里的问号。

## 根因与修复

### 1. 字体选择依赖系统语言，字形范围过窄

原实现仅调用 `plGetSharedFont(languageCode, ...)`，然后使用一份稀疏的 `nxFontRanges`。在非中文系统语言下，简体中文字体可能不参与；即便字体包含某个汉字，未被范围列入也不会进入图集，最终被替换成缺字字符。

现在保留系统语言字体优先级，再去重补载标准、简体中文、扩展简体中文和繁体中文共享字体；图集范围合并原有字符与 CJK 基本区、扩展 A、兼容汉字、中文标点、注音和全角字符。字体不可用时记录错误并继续使用已有字体；字体图集构建失败不再被忽略。

没有分发 Nintendo 字体，字形来自用户自己的主机。全范围是“允许图集收录”，不等于实际字体覆盖全部 Unicode。

### 2. 字幕缺少可靠的中文默认字体

原启动逻辑只导出标准共享字体，并在该文件已经存在时完全跳过字体准备。现在逐个缓存可用字体到 `sdmc:/switch/SwitchWave/fonts/`，并在没有用户自定义文件时创建 `sdmc:/switch/SwitchWave/subfont.ttf`。优先采用简体字体，缺失时采用繁体或标准字体。mpv/libass 有明确默认字体路径，ASS 精确匹配和嵌入字体仍然优先。

写入先用临时文件，确认写入和关闭成功后再重命名。用户已有 `subfont.ttf` 不覆盖。启动在进入字体图集前等待字幕字体准备结束，避免两个线程并发操作 `pl` 服务或首次播放早于字体准备。

注意：devkitPro 的 libass 没有通常桌面环境的 fontconfig 后端，仅缓存多个字体不保证自动跨字体回退。默认字体仍可能缺少特定繁体字或罕用字；此时需要用户提供兼容的 `subfont.ttf`，不声称已经实现完整字体回退系统。

### 3. 字符数和 UTF-8 字节位置混用

原配置编辑器按 `stringLen` 差值移动原始字节，网络设置也用字符长度判断 31 字节缓冲区；控制台直接把键盘光标交给 ImGui。这会截断汉字、错位或误删。

现在使用键盘 UTF-16 回复模式，libnx 仍将回调文本转换为 UTF-8；单独转换 UTF-16 光标和 UTF-8 字节位置，处理代理对。配置编辑器保留光标附近的实际文本窗口，不再每次按键重置为空格；这样输入法可以把拼音/候选词作为整体替换，已有文字的插入、前后删除和光标移动也不会拆开汉字。窗口超过适当长度时只在没有候选词组合的情况下重新居中，避免超过系统键盘文本限制。网络/控制台按实际字节检查容量，不接受截断后的非法 UTF-8。已有网络字段容量不扩大，31 字节通常最多容纳 10 个常见汉字。

### 4. 长中文路径被固定缓冲区二次截断

原实现先取末尾 43 个 UTF-8 字符，却又塞入 50 字节缓冲区；43 个汉字远超过 50 字节。现在动态保存末尾 43 个字符，并只在确实删去前缀时添加省略号，不再按字节截断。

### 5. GBK/GB18030 字幕没有转换能力

上游构建显式 `--disable-iconv`。现在 Docker 构建并校验 GNU libiconv 1.18 源码 SHA-256，mpv 改为 `--enable-iconv`；手动构建提供 `misc/libiconv/PKGBUILD`。应用与默认配置使用 `sub-codepage=gb18030`，保留有效 UTF-8/BOM 优先识别；本地 `mpv.conf` 可以覆盖为 `big5` 等编码。

这不是编码自动检测：非 UTF-8 的西文或其他语言字幕应指定对应编码。不会根据显示结果猜测并改写文件系统的原始路径。

只编译/安装 libiconv 库与公共头文件，不编译不需要的命令行工具及其 gnulib 兼容层；后者与 devkitPro/newlib 的系统头文件存在冲突，首次远程构建已复现该问题并据此缩小构建目标。

## 安装与实机验收

1. 从功能分支构建，使用 Docker 或在现有 devkitPro 中安装 libiconv 后重新配置/编译 mpv。
2. 备份 SD 卡原配置，更新 `.nro`，保留原目录；不需要删除字体目录，也不要直接覆盖已自定义的 mpv.conf。
3. 分别在中文/英文/日文系统语言下检查 `中文视频/测试电影.mkv`、`繁體影片/測試.mkv`，确认显示与播放都正常。
4. 测试超过 43 字符的深层中文路径，末尾不能出现半个汉字或问号。
5. 网络设置测试 `中文共享`、31 字节边界、多字节溢出拒绝，以及插入/删除/光标移动。
6. 配置编辑器测试中文注释、中文目录、一次提交多个字、连续退格、空格与换行；保存后再次读取确认没有编码破坏。
7. 控制台测试中英混排及历史回填。4 字节字符只检查编辑边界，显示与否仍受字库限制。
8. 播放 UTF-8、UTF-8 BOM、GBK、GB18030 中文字幕，Big5 字幕显式设置 `sub-codepage=big5`；比较同一字幕升级前后的结果。
9. 检查新字体图集对启动耗时、应用内存及 applet/完整应用模式的影响。中文全范围比原图集更大，需实机评估。

## 验证记录与边界

- 版本 `1.1.2-zh.1` 的独立主机回归覆盖全部 215 个词条的检索、printf 参数格式和中英切换后的 ImGui ID，一并覆盖非法路径、跨挂载点、文件名含中文与 `##`、普通文件删除、目录/链接拒绝、历史文件清空及失败返回；通过 AddressSanitizer/UndefinedBehaviorSanitizer。这里使用本地临时文件和主机设备接口桩，不代表 Switch 或真实 SMB/NFS/SFTP 服务器验收。

- 本地独立回归程序通过 GCC 的 AddressSanitizer/UndefinedBehaviorSanitizer 检查，涵盖中英混排、4 字节字符/代理对、前后删除、光标钳制、非法 UTF-8、空格、多字提交、拼音候选词替换和容量拒绝，另通过 2,000 组生成的文本窗口编辑。项目原来没有测试框架，因此没有为本次修改强行增加框架。
- 补齐真实第三方头文件与 FFmpeg 生成头后，Switch 的 `aarch64-none-elf-g++` 已通过全部六个修改 `.cpp` 的语法检查。语法检查不单独作为链接成功依据。
- 在本机已有中文字体上使用本项目固定版本 ImGui/FreeType 做范围对照：原范围图集 7,867 个字形，新范围 29,307 个字形，其中新增收录 14,310 个 CJK 基本区字符，图集 4096 × 2384。这验证字符范围修复，不代表 Switch 系统字体有相同覆盖率。
- 2026-10-01，提交 `3120c26` 的 GitHub Actions 构建 `36824335384` 已通过工具链镜像、SwitchWave NRO 完整编译/链接、ZIP 打包与产物上传。首次失败的 libiconv 工具兼容层问题已通过仅编译库修复。后续仅文档提交不改变该已构建源代码。
- 没有 Switch 实机测试，不宣称所有汉字、字幕和输入法情形均已验证；实机字库、候选词过程、启动耗时、内存和 applet 模式仍按验收清单检查。
- 补充平面的生僻汉字、emoji、字体本身缺字、上游已经写成字面 `?` 的内容不保证修复。
- 现有网络协议的非 UTF-8 文件名/目录页编码不做盲目猜测。SMB 转码仍由 libsmb2 负责，NFS/SFTP 应由服务端提供 UTF-8；不能仅凭字形缺失判定原文件名应为 GBK。
- 发现的一些既有通用健壮性问题，例如 `read_whole_file` 对空文件指针调用 fclose 的风险，与中文任务无直接关系，没有顺手修改。
